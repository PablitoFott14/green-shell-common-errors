4.3Category and Evaluation Target filled with the wrong kind of value

Costs pointsRubric Criteria - Overall Rubric Quality

The mistake

Category or Evaluation Target does not fit the criterion: Agent Behavior or Tool Use on an artifact, a category in the target field, or a subjective row tagged Instruction Following.

Do this instead

Retag, do not rewrite: a check on a file takes the deliverable's category, and an explicit ask moves from the subjective block to the objective one.

Catch it in your own task

Read each category beside its target: Agent Behavior and Tool Use only on Trajectory, every subjective row Task Completion.

Guidelines · 5.4 Category & Evaluation Target

If you wrote Agent Behavior against an artifact, a state change or the final message, you picked the wrong category: you are grading the deliverable, which is Task Completion or Instruction Following.

Agent Behavior: Target Trajectory, always.

Guidelines · 5.4 Category & Evaluation Target

People tend to underestimate the importance of these two fields, but they play a major role in how rubric data is structured, delivered to the client, and interpreted downstream.

Guidelines · 7.4 Categories and Evaluation Targets for Subjective Rubrics

Task Completion is the only valid category for subjective rubrics.

Guidelines · 5.6 How the Client Defines Rubric Issue Severity

The criterion can be rated, but it is built wrong: redundant, vague, misplaced, misweighted or pointed at the wrong thing.

Moderate, which fails the task above 15%. Its named types include Overlapping or Redundant, Overfitting and Underfitting, Incorrect Weights, Block Bleed and Miscategorized.

Why it matters

Category says what kind of check it is; target says where the grader looks. Both shape how the rubric data is structured and delivered to the client, so a wrong pair is wrong data even when the criterion is right. Agent Behavior and Tool Use grade how the run got there, so they sit on Trajectory, inside the 20% process cap: one pointed at a file, a state change or the final message is grading the deliverable and needs the deliverable's category. In the subjective block Task Completion is the only valid category, because anything the prompt explicitly asked for belongs in the objective block.

## THE RULES

### Checklist ("HH move - do not screw this up", written Aug 15)
1. laptop → T7 (Finder copy)
2. verify T7: every album, item **count AND size** match laptop
3. T7 → mini
4. verify mini the same way
5. wipe laptop **ONLY** when steps 2 **and** 4 are clean

Checks:
- **count AND size both off → STOP, hold everything**
- **size off only → recopy that album, no hold**
- **archive folder: count + size only, don't open it**
- 7 albums, ~213 GB (the 7 folders that are NOT `bc eagles 3-21`; that set sums to 213.2 GB)
- finale: 191 clips + project + autosaves. **autosaves ARE the edit.**
- names stay EXACTLY as on disk (Premiere relinks break)
- **double-check any album modified after the drive showed up** (drive = May 6, 2026)

### Voice note (the parts not on the checklist) — transcribed from "New Recording 47.mp3"
- **Any album with only one copy anywhere → automatic HOLD.** Don't wipe, no matter what else passes.
- The wipe call at the end must **name what is blocking**, by name — not just yes/no.
- The finale: **the cut IS the autosaves.** If those don't survive, the whole thing was pointless.
- Card readers are in the desk drawer (for pulling anything off the cards).

Only two things moved; everything else copied through T7→mini identically.
1. **Finale got worse.** T7 finale = 59.3 GB with autosaves apparently intact (size = laptop minus only the slowmo tests). Mini finale = 59.1 GB with **Auto-Save = 0 items** — the ~11 autosave files (~0.2 GB) present on the T7 were dropped in the T7→mini copy. This is exactly the "autosaves ARE the cut" failure.
