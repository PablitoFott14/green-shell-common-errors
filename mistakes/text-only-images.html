1.2Images that are only pictures of text

Fails a client CORE standardHard Client Requirements · Multimodal

The mistake

Every image in the input set is a document in picture form: a screenshot, a printed page, a handwritten copy. The model only has to transcribe it, never to interpret it.

Do this instead

Ask what the model has to do with each image. If the answer is read the words, it is a document in picture form, so make sure most image slots go to something that has to be looked at: a photographed object, a chart, a map, a scene.

What is wrongBoth images are text in picture form: IMG_4471.jpg is a handwritten copy of the returns card and the order page is a screenshot. The scenario's photo of the returns card itself never reaches the task.

A runner wants to send back whatever still qualifies from a split Marathon Sports order. The inputs are two images and a voice memo.

Where it shows

IMG_4471.jpg
A handwritten note headed "copied off the card in the box": return windows, struck out figures and an address, all words and numbers.
Order page screenshot
The order page as a screenshot: item names, prices and tracking lines, all text.
Prompt
I copied the returns stuff off the card that was in the box and then the box went out with the recycling, so that scrap is all I have left of it.
Scenario
Screenshot of my order page and a photo of the returns card that came in the box.

What it should have been

Inputs
The returns card the scenario names, photographed as it came in the box, and images the model has to interpret rather than read, such as the items themselves, since worn or unworn decides which window applies, so that text is no longer most of what the images carry.

How it breaks the standardThe client asks for images that need genuine visual interpretation. Here both images are transcribed, never interpreted, and the handwritten copy replaces the one object the scenario asked to be photographed.

The rule it breaksGuidelines · 1.1.2 Rest of the Parameters Most images should need real visual interpretation, not be screenshots of text. The third input, voice_memo_0928.mp3, is audio.

Catch it in your own task

Finish this sentence for every image: the model has to look at it to... If most answers are read what it says, the set is text in picture form.

Where the correct guidance is written

Section titles as they print, so you can search for them in the document.

Guidelines · Hard Client Requirements for Every Task

We need to avoid majority of the images used as part of the multimodal context to be primarily text-based.

The Multimodal requirement, marked [NEW].

Guidelines · 1.1.2 Rest of the Parameters

Most images should need real visual interpretation, not be screenshots of text.

The row for Input modalities.

Guidelines · 1.2.2 Select the Multimodal Inputs

Most images should require genuine visual interpretation (photographs, diagrams, charts, maps, real-world objects), not screenshots of text.

QC spec · Input Artifacts - Minimum Multimodal Inputs

Minimum 3 multimodal inputs in the Model A conversation. Three is the minimum, not the target; intentional distractors count.

Fewer than three fails the task.

Why it matters

Image diversity is a client requirement, marked new in the Green Shell Guidelines: most of the images used as multimodal context must not be primarily text based. A set made only of screenshots and copied notes tests transcription, not the visual interpretation the client is paying for.

Went a bit mad on the Marathon Sports summer sale back in August and I'm regretting most of it. That order came in two lots and I want to send back everything I can still send back. Screenshot of the order page is attached, plus a photo of the note I scribbled when the first parcel turned up. I copied the returns stuff off the card that was in the box and then the box went out with the recycling, so that scrap is all I have left of it. There's a voice memo in there as well, I recorded it on the way to work and there's a couple of things in it you'll need. Everything in that order is unworn and still in its bags apart from the Hoka Cliftons, which I have been running in since they arrived, so treat those differently to the rest. Work out which ones I am still in time on. For anything that qualifies, go ahead and actually send the return request off to them for me, one email covering the lot. Anything that has run out, don't email about it, just tell me on the page. One more thing about that note, because I don't fully trust my own copying. Two of the numbers on it I wrote down, crossed them out and wrote them again. Tell me what the crossed-out ones actually say, and then work out which items would come back into play if it turns out I had it backwards and the crossed-out figures were the right ones. I'd rather know now if there is anything worth ringing them about. Save the working as "returns_check.html" so I can see how you got there. I want every item on it, whether each one is in or out, which rule you applied to that item and the dates you counted from, and a copy of whatever you end up emailing them. Put the total I'm getting back on there too, so I know what to expect on the card, and roughly when that money should land. I'm hopeless with this stuff. Last time I sat on a return for weeks and missed the window completely, so I'd rather find out now than in November. And tell me anything else I should watch out for here, I always seem to get caught out on something.
