1.1The deliverable sits below the complexity bar

Fails a client CORE standardComplexity Bar

The mistake

The deliverable misses its type's complexity floor. Typically the Agent Objective says dashboard, the prompt never asks for interaction, and the page ships static.

Do this instead

While you design the scenario, check the deliverable type against its floor, and have the prompt ask for the interaction the data supports.

Where it happened in Red Shell

One real Red Shell task. Each shows the spot and what it should have been; click any line to open the task there.

What is wrongThe Agent Objective asks for "one local HTML dashboard"; the golden ada_list.html has no script, button, filter or link. Static, it clears neither the dashboard nor the interactive HTML floor.

What it should have been

Leg A turn 1

How it breaks the standardNothing on ada_list.html responds, so the task ships a document, the lowest priority type on the Complexity Bar, though 14 Fresh orders could feed sorting or filters. Model A and Model B never see the Agent Objective, and no Leg A prompt asks for interaction, so no criterion grades it.

The Green Shell rule it breaksGuidelines · Complexity Bar A styled static page does not qualify. The Interactive HTML floor, P0. A dashboard's, also P0, is several linked views.

Catch it in your own task

Ask what the page does when someone clicks it. If nothing, it is a document, whatever the Agent Objective calls it.

Where the Green Shell guidance is written

Section titles as they print in the Green Shell Guidelines and QC spec, so you can search for them.

Guidelines · Complexity Bar

Interaction that actually works: controls that respond, state that changes, filters or navigation. A styled static page does not qualify.

The floor for Interactive HTML, a P0 deliverable.

Guidelines · Complexity Bar

Several linked views over data the model extracted itself. One chart is not a dashboard.

The floor for a Dashboard, also P0.

Guidelines · Complexity Bar

Raising the complexity standard from Blue Shell has been one of the clearest and most consistent client requirements.

Guidelines · 1.3 Defining the Draft History

The Draft History (Agent Objective, Desired Outcome, Multimodal Upload) is not embedded in the agent by default. The prompt and multimodal context are the only context the agent has access to, so never assume a requirement is in play just because you wrote it down here.

So only the prompt can ask for a dashboard.

Why it matters

A page that does nothing when clicked clears neither the interactive HTML floor nor the dashboard floor. It is a document, the lowest priority deliverable on the bar, so the task falls short of what the client asked for however good the reasoning underneath is. Only the prompt and the inputs reach the agent, so the floor has to be asked for in the prompt, and the deliverable cannot be patched once the runs exist.

From the taskAgent Objective
Winslow Achebe is picky about grocery brands, and this time, Adaeze is the one going to the store. While he was writing his shopping list, someone at the office pushed some cheaper lookalike products on him. He needs one local HTML dashboard, 'ada_list.html ', that Ada can use at the store, where his sticky list becomes a detailed shop sheet (brand, product, price, amount, and product picture), and it includes a clear comparison of the tip products against what he already buys on Amazon Fresh, with a fixed KEEP TIP or SKIP TIP call.
From the taskEvery Leg A prompt, to Model A
Leg A turn 1
Ada called; she's going to the store after work, and I was making my list for her when I was told I could change some products. I got some pics of the products (proteinbars.png, gfacts.png, and gimage.png), and I need to create a comparison table for the products I usually buy, coz I'm really picky about my things. I also need to create an "ada_list.html" where I need to have the items from the list I uploaded, with the amounts I usually buy. It should be detailed, like brand, price, size, and a pic of them, so Ada doesn't get them wrong.
Leg A turn 2
I only asked for one HTML. I need you to check the swaps with this rule: KEEP TIP only when the new product is lower priced than my usual and organic. Protein should be at least 10g, and the OJ should have Calcium and vitamin D. Otherwise, SKIP TIP.
Leg A turn 3
Okay, that's better for comparison, but you didn't really research either. Also, the page should be focused on the list first, and you are asking me to write the data you have. It needs brand, price, size, amount, and a product picture. Don't invent it you have the data.
